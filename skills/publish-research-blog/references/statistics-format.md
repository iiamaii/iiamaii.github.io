# 논문 통계 데이터

```sh
npm run stats:new -- analysis-id
```

`content/statistics/analysis-id.json`을 비공개로 생성한다. [템플릿](../assets/statistics-analysis.json)의 예시 문구·주소를 실제 분석으로 교체하고, `null`을 확인한 숫자로 채운다. 공개하려면 검증 후 `visibility`를 `public`으로 바꾼다. 비공개 자료는 공개 저장소에 커밋하지 않는다. 기본 템플릿은 코드 검사용 예시이며 연구 데이터가 아니다.

## 집계 단위와 갱신 대상

- **리뷰 수**는 공개된 `translationKey` 개수다. 한영 번역은 한 편으로 센다. 비공개·초안·미래 발행 원고는 제외하며 실제 빌더와 같은 공개 집합을 사용한다.
- **고유 논문 수**는 원문 식별자로 묶는다. arXiv는 abs/pdf/html URL과 버전 차이를 제거한 ID, DOI는 정규화한 DOI, 그 밖에는 원문 URL(프래그먼트 제외)을 쓴다. 같은 제목이라는 이유만으로 합치지 않는다. DOI와 arXiv처럼 서로 다른 식별자 사이의 동일성은 자동 추정하지 않으므로 같은 논문의 `paperUrl`을 원고에서 통일한다.
- **원문 실험 분석**은 해당 버전·표·그림을 대상으로 한다. 새 포스트 추가와 독립적이며, 근거·수치·조건·대상 범위가 달라질 때 다시 확인한다. 단순 재확인으로 `updatedAt`을 바꾸지 않는다.

주제 집계의 관리 파일은 `content/statistics/review-topic-snapshot.json`이며 `npm run stats:update`가 갱신한다. 이 파일은 다른 수동 분석에 재사용하지 않는다. 파일이 없으면 공개 메타데이터로 생성하고, 이미 비공개인 파일은 공개로 바꾸지 않는다. 공개 리뷰가 0개면 빈 차트를 만들지 않고 관리 파일을 제거한다.

1. 같은 논문을 다루는 공개 연재 중 `[n/N]`의 `n`이 가장 작은 글을 대표 리뷰로 고른다. 동순위·번호 없는 글은 `translationKey` 순서로 고른다. 주제 순서는 한글 공개 원고, 한글이 없으면 영어 원고를 따른다.
2. 막대는 대표 리뷰의 첫 주제별 **고유 논문 수**다. 막대 합계와 그래프 노드 수는 고유 논문 수와 같다. `paperSlugs`와 출처에는 집계에 사용한 모든 공개 리뷰를 남긴다.
3. 논문별 주제는 공개 연재의 주제 합집합이며, 두 논문 사이 교집합의 원소 수를 무방향 간선 가중치로 쓴다. 공통 주제가 0이면 간선을 만들지 않고 고립 노드는 유지한다. 대표 리뷰가 비공개가 되면 남은 공개 글에서 다시 선택한다.
4. 변경된 데이터만 저장하고 실제 재계산 시각을 기록한다. 데이터가 같으면 파일과 `updatedAt`을 유지한다. 기존 노드의 짧은 한영 라벨은 유지할 수 있으며 원문·연재 식별은 라벨이 아니라 위 식별자로 처리한다.

현재 네트워크는 40개 노드까지 지원한다. 이를 넘으면 임의로 일부를 버리지 말고 문서화한 범위로 분석을 나누거나 구현을 확장한다.

## 공통 필드

| 필드 | 규칙 |
| --- | --- |
| `schemaVersion` | 현재 `1` |
| `id` | 영문 소문자·숫자·하이픈, 공개 분석 사이에서 유일. 발행 후 유지 |
| `visibility` | `private` / `public`. 생략하면 비공개 |
| `updatedAt` | 실제 작성·재분석 시각. 초와 시간대가 있는 ISO 8601. 미래 시각은 해당 시점 이후 재빌드해야 노출 |
| `title`, `summary`, `notes` | 모두 `{ "ko": "한글", "en": "English" }`. notes에 버전·데이터셋·조건·집계 방식·한계를 기록 |
| `paperSlugs` | 관련 공개 리뷰의 `translationKey` 배열. 외부 논문만 분석하면 빈 배열 가능 |
| `sources` | 하나 이상. `{ "url": "https://…", "label": {"ko":"…","en":"…"}, "location": {"ko":"Table 2…","en":"Table 2…"} }` |
| `charts` | 하나 이상의 차트. id는 분석 내에서 유일. title·description은 한영 객체 |

URL은 HTTP(S)만 허용하고 모든 문구는 실행되지 않는 일반 텍스트로 표시한다. 공개 데이터의 잘못된 숫자·존재하지 않는 노드·비공개 리뷰 연결은 빌드를 실패시킨다. 단위가 같아도 데이터셋·분할·표본 수·평가 설정이 다르면 직접 순위로 비교하지 않는다. 표를 발췌할 때 기준선·주 비교군과 제안법보다 나은 행을 보존하고 Oracle·실측·인용값의 역할을 구분한다. 평균·변환값은 계산식을 남기며 반올림된 원문 평균은 그대로 옮긴다. 수치·출처 위치와 한영 문구를 함께 수정하고 유의성·인과 관계를 분석하지 않았다면 주장하지 않는다.

## 막대그래프 `type: "bar"`

- `unit`: 한영 단위. 무단위 지표도 명시한다.
- `direction`: `higher` / `lower` / `none` (높을수록 좋음 / 낮을수록 좋음 / 단순 빈도·크기).
- `values`: 1–100개 `{ "label": {"ko":"…","en":"…"}, "value": 0.538 }`.
- 유한한 숫자만 허용한다. 누락을 0으로 바꾸지 않는다. 미확인 항목은 차트에서 제외하고 notes에 남긴다. 음수·0도 지원하며 축은 0을 포함한다.

## 관계 그래프 `type: "network"`

```json
{
  "id": "shared-topics",
  "type": "network",
  "title": {"ko": "주제 관계", "en": "Topic links"},
  "description": {"ko": "두 논문에 공통인 주제 수", "en": "Count of shared topics"},
  "relationship": {"ko": "무방향 · 공통 주제 수", "en": "Undirected · shared topic count"},
  "nodes": [
    {"id": "paper-a", "label": {"ko": "논문 A", "en": "Paper A"}},
    {"id": "paper-b", "label": {"ko": "논문 B", "en": "Paper B"}}
  ],
  "edges": [{"source": "paper-a", "target": "paper-b", "weight": 2}]
}
```

1–40개 노드, 연결 없는 노드도 표시한다. label은 짧게 작성한다. 노드에 선택적으로 `paperSlug`를 넣으면 공개 리뷰로 연결한다(`paperSlugs`에도 포함). 현재 지원 범위는 **무방향 가중 관계**이며 `weight`는 양수다. 자기 자신·중복 연결·없는 노드는 거부한다. 인용 방향·시간 흐름이 필요한 분석은 이 형식에 억지로 넣지 않고 새 차트 유형을 구현한다.

## 검증과 갱신

```sh
npm run stats:update
npm test
npm run build
```

리뷰 추가·공개 전환·삭제, 주제·원문 URL·연재 순서·표시 이름 변경 시 실행한다. 명령은 빌더의 공개 판정을 재사용하며 다른 실험 분석은 수정하지 않는다. 일반 빌드는 관리 집계의 차이를 발견하면 실패하고 갱신 명령을 안내한다. 일반 빌드가 원본 JSON을 자동으로 덮어쓰지는 않는다.

`git diff`로 대상 집합·막대 합계·노드 수·간선 가중치·대표 링크·출처를 확인하고 영향받은 원고와 집계 JSON을 같은 커밋에 포함한다. 날짜만 바뀌는 변경을 만들지 않는다. 공개 취소로 수동 분석의 `paperSlugs`가 유효하지 않게 되면 연결 대상이나 분석 공개 범위를 수정한 뒤 빌드한다.

`/statistics/`, `/en/statistics/`에서 분석 선택·두 테마·모바일·데이터 표·출처를 확인한다. 차트는 정적 HTML/SVG로 생성되므로 JavaScript 없이도 전체 분석이 보인다. 새 차트 유형은 검증기(`scripts/statistics.mjs`)와 렌더러(`scripts/render-statistics.mjs`), 테스트·이 형식을 함께 확장한다.

첫 화면의 리뷰·주제 수는 빌드 시 현재 공개 자료로 계산한다. 개별 JSON은 저장된 분석이며 관리 주제 집계만 위 명령으로 재계산된다. 실험 분석은 원문을 확인해 직접 갱신한다. 작업 인계에는 분석 경로·공개 여부·변경 이유·집계 단위와 입력 집합·계산 근거·원문 위치·검증 결과·미확인 항목을 남긴다.
